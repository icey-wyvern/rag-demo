# Demo walkthrough

Use a corpus that has already been populated with versioned passages; Hybrid and Semantic also require indexed embeddings and a configured query embedding provider. [Full application setup](../readme.md#run-the-full-application) uses live GOV.UK acquisition and OpenAI. For a credential-free engineering review, run the [offline and PostgreSQL checks](../readme.md#verify-without-api-credentials) instead. The walkthrough does not assume a particular live guidance body is present.

1. **Current observed guidance:** open the UI at `http://localhost:8080`. Leave retrieval at **Hybrid** and answer mode at **Generative**. Ask a question relevant to a source actually loaded in the corpus. Read the answer, then inspect each claim's cited source and exact supporting quote. The response comes from the latest locally observed snapshot for each source.
2. **Retrieval modes:** repeat a corpus-relevant question in **Lexical**, **Semantic**, and **Hybrid**. Lexical ranks PostgreSQL full-text matches; Semantic ranks matching provider/model embeddings by pgvector cosine distance; Hybrid fuses ranks with RRF. The modes can return different passages. No mode is asserted to be universally best.
3. **Observed-as-of query:** choose **Observed as of**, enter a local date/time after an earlier observation and before a later observation of the same source, and submit a relevant question. The UI sends a timezone-aware timestamp. The cutoff selects the latest snapshot **this corpus had observed by that time**, not an authoritative GOV.UK historical state. Clear the field to return to the latest observed corpus.
4. **Abstention:** if retrieval returns no usable evidence, generated mode returns an abstention without calling the answer provider. The provider can also abstain when supplied evidence is insufficient. The UI shows the reason without supporting-source cards. A natural-language question is not guaranteed to produce no evidence in every populated corpus; the offline evaluator tests this outcome deterministically.
5. **Chunks only:** select **Chunks only** and submit a question. The UI shows retrieved passages and provenance for inspection without a generation call. These passages are retrieval results, not validated answer citations.
6. **Provenance:** for an answered result, inspect the cited quote, source link, observation time, and available source-update time. Expand **Technical provenance** for snapshot/passage identifiers and hashes. The observation time is the local corpus timestamp used for temporal selection; source-update time is source metadata.

Internal version comparison is available through `VersionComparisonService` and `VersionChangeSummaryService`, not through this UI. The comparison derives added, removed, modified, and unchanged passage records by ordinal/hash, with older/newer provenance. Its optional summary uses the same citation validator. See [architecture](architecture.md#version-comparison).
